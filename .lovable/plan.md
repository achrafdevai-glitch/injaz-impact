# تطوير مبادر | MUBADIR

## نتيجة الفحص
- التسجيل وصورة البطاقة متصلان حاليًا بـLovable Cloud؛ بقية النشاط والتحديات والنقاط والمكافآت تعتمد على بيانات تجريبية محفوظة في الجهاز.
- لا توجد حاليًا صلاحيات مشرفين أو سجلات مركزية للمشاركة والمراجعة.
- سنحافظ على الصفحات الحالية والشعار والألوان والشريط السفلي وتكوين خريطة الأثر، دون إعادة بناء التطبيق.

## الأعمال
1. **الهوية:** استبدال إنجاز / INJAZ بمبادر / MUBADIR في الواجهة والعناوين ووصف المشاركة وملفات التطبيق، مع الشعار الحالي والشعار النصي «خطوة منك... أثر في مجتمعك.».
2. **بيانات حقيقية:** حفظ الملف العام للمتطوع، وربطه بالتسجيل الخاص، وحفظ التصنيفات والتحديات والمشاركات والإثباتات. تبدأ قوائم النشاط فارغة حتى ينشئ المشرف محتوى فعليًا؛ لا تُنقل الإنجازات التجريبية إلى أرصدة حقيقية.
3. **رحلة التطوع:** اكتشاف تحدٍ منشور ← انضمام بحساب مسجل ← وصف النشاط ورفع صور أو فيديو إلى مساحة خاصة ← إرسال للمراجعة ← قبول أو رفض مع السبب ← تحديث الرصيد وساعات التطوع وXP والأوسمة بعد القبول فقط.
4. **لوحة الإشراف:** إنشاء التحديات وتعديلها ونشرها وحذفها من العرض؛ مراجعة الإثباتات مع معاينة الملفات وأسباب الرفض؛ عرض المتطوعين وأنشطتهم والإحصاءات؛ إعداد المكافآت وتتبع طلبات الاستبدال وحالتها. تُؤرشف التحديات المرتبطة بأنشطة بدل محو تاريخ التطوع.
5. **النقاط والترتيب:** احتساب الأرصدة على الخادم، منع منح الرصيد مرتين ومنع تعديله من المتطوع، وتسجيل كل زيادة أو خصم. حساب المستوى والفئة وفق الصيغ الحالية. ترتيب حقيقي حسب البلدية والولاية والوطن، دون أسماء أو أرقام تجريبية.
6. **المكافآت:** عرض المكافآت المنشورة من المشرف فقط، والتحقق من الرصيد والمخزون ومنع الطلبات المكررة، وحفظ سجل الاستبدال وحالته. لا تظهر وعود بامتيازات أو شركاء غير مهيئين.
7. **تجربة الاستخدام:** حالات انتظار وفراغ ونجاح وفشل، وصول واضح للدخول والخروج، وتحديث البيانات بعد العمليات وعند تغيير الحساب. الإبقاء على اللغة داخل الإعدادات فقط.
8. **التحقق والتوثيق:** تجربة الرحلة بحساب متطوع وحساب مشرف وملف إثبات غير حساس، واختبار منع التكرار وتعديل النقاط والوصول غير المصرح، وفحص الهاتف؛ تحديث README بهوية مبادر والجداول والوظائف المنفذة والقيود الفعلية.

## التفاصيل التقنية
- إعادة استخدام TanStack Start ومكونات الواجهة وLovable Cloud والاتصال الحالي؛ استخدام وظائف خادم محمية للمراجعة والإدارة والعمليات المالية.
- إضافة جداول مترابطة للملفات العامة، الأدوار، التصنيفات، التحديات، المشاركات، الإثباتات وملفاتها، الأرصدة، سجل النقاط، الأوسمة المكتسبة، المكافآت وطلبات الاستبدال، مع صلاحيات صريحة وسياسات وصول لكل جدول.
- إبقاء بيانات الهوية الخاصة منفصلة عن الملفات العامة والترتيب. الملفات الخاصة لا تُعرض إلا لصاحبها وللمشرف المخوّل بمراجعة إثباتات النشاط؛ بطاقة الهوية تبقى ضمن الحماية الحالية.
- تنفيذ القبول والاستبدال كمعاملات ذرّية تتحقق من صلاحيات الحساب وتقفل السجلات وتمنع التكرار. لا توجد صلاحية للمتطوع لتحديث الأرصدة مباشرة.
- الاحتفاظ بالتفضيلات والترحيب فقط في التخزين المحلي، وإلغاء اعتماده كمصدر للنشاط. إعادة استخدام تحميل البيانات وتخزينها المؤقت عبر TanStack Query.
- إضافة التغييرات عبر أدوات ترحيل Lovable Cloud، وإضافة اختبارات لقواعد النقاط والاستبدال والصلاحيات.

## ما يحتاج تهيئة
- تعيين أول مشرف يتطلب اختيار حساب مخوّل منك؛ لن نمنح الصلاحية تلقائيًا لأول مسجل أو لأي حساب عشوائي.
- التحديات والمكافآت والشركاء الفعليون ينشئهم المشرف. اختبار بيانات النشاط يُستخدم للتحقق فقط ويُزال بعده، ولا يُعرض كنشاط حقيقي.
- لا يمكن ضمان عمل التطبيق بنسبة 100%؛ التقرير النهائي سيذكر ما اختُبر بالفعل وما بقي غير متحقق، بما فيه تسليم المكافآت خارج التطبيق وسياسات الاحتفاظ لدى مزود فحص الهوية.
